# Architectural Assumptions Register

Distinct from `docs/adr/` — an ADR records a decision already made; this records things we currently *believe* and are building on. If evidence later rejects one, that's an explicit trigger for a new ADR, not a silent pivot. | A-008 | Per-location historical-signature features (ACF/persistence-based) will be Project Phase 4's single highest-leverage feature category — more impactful than region/season/onset-state features for handling blackout staleness | High | **Validated by Experiment 3** (`notebooks/02_forecastability.ipynb` §9-10): stratifying the blackout-degradation curve by per-location ACF(1) quartile produces the widest RMSE spread at k=9 (0.403) of any of the four tested cuts — nearly 2x the next-largest (latitude band, 0.191), and far ahead of season (0.079) and onset drought regime (0.066). Nuance: low-ACF locations are worse in absolute terms at every horizon, while high-ACF locations degrade proportionally faster (more room to fall) — both facts should inform the feature design, not just "ACF matters." An AR(1) theoretical model correctly predicts the curves' shape/ordering but systematically over-predicts absolute error, suggesting real exploitable structure (seasonality, longer memory) beyond simple lag-1 persistence — the specific gap historical-signature features are meant to close. | Validated | Project Phase 1, Experiment 3 (complete); re-confirm empirically once Phase 4 features are actually built and ablated |
| A-009 | The in-sample persistence RMSE (0.572, Baseline A) meaningfully understates the real test set's naive-baseline difficulty, because it's only achievable on months where `TWS_t` is actually observed | High | **Validated by Experiment 4** (`notebooks/02_forecastability.ipynb` §11-12): reconstructed the real 18-month test temporal structure (6 FULL + 12 BLACKOUT offsets) and found the 12 blackout months carry staleness-to-target k=2 through k=7 (not a fixed value — distribution k=2×4, k=3×3, k=4×2, k=5/6/7×1 each), correcting a subtle definitional issue first (staleness must be measured to the *target* month, row_month+1, not the row's own month). Two independent methods — Method A (reweighting Experiment 3's validated RMSE(k) curve by this real distribution, RMSE≈0.7091) and Method B (direct replay of the exact real pattern onto 8 independent windows of verified clean 2004-2010 history, ground-truth scored, RMSE=0.7145) — agree within 0.005 pooled and 0.028 mean-abs per-offset. Full baseline picture on the real/replayed test structure: A (oracle, FULL only) 0.5247, B (last-known, BLACKOUT only) 0.7145, C (climatology) 0.817, D (Hybrid, all 18 months) 0.6573. Baseline D, not Baseline A's 0.572, is the real "do nothing clever" floor for this competition's actual test structure. | Validated | Project Phase 1, Experiment 4 (complete); Project Phase 3 will recompute inside the formal validation harness for the official record |
| A-010 | "Months since observation" (staleness, k) needs to be interacted with location-dynamics (ACF/volatility), not used as an isolated state variable, when reconstructing hydrological state | High | **Validated (nonlinearly) by Experiment 5** (`notebooks/02_forecastability.ipynb` §13-14): a direct linear-interaction regression (`error^2 ~ k + acf1 + k*acf1`) found the interaction term added ~0 R^2 (0.0645→0.0645) — but this is a functional-form artifact, not evidence of no interaction. The AR(1) theoretical model (parameter-free, driven only by each ACF-quartile's ρ and σ) explains R^2=0.448 of the empirical curve's variance, and a 10-way ACF-decile stratification is monotonic at 9/9 values of k — both confirm a real, strong, continuous k×ACF relationship that the linear test simply used the wrong (multiplicative) functional form to detect (the true relationship is ρ^k, not k·ρ). A confound check further found TWS volatility (σ) is a largely independent signal from ACF (r=-0.141 across 15,715 locations) and adds substantially more explanatory power (+0.0462 R^2, +71.6% relative) than the ACF-only interaction term did — σ should be tracked as its own state-dynamics signal, not assumed subsumed by ACF. | Validated (nonlinear form) | Project Phase 1, Experiment 5 (complete); re-confirm empirically once Phase 4 features (raw components vs. explicit AR(1)-motivated composite) are built and ablated against each other |

| A-013 | The validation harness's Tier 3 (`validation/tiers.py::run_tier3`) faithfully reproduces Phase 1's measured reality once (a) its replay anchors are restricted to the verified clean 2004-2010 span, matching Experiment 4 Method B's own design, and (b) its deliberate row-wise, stateless-between-offsets scoring is accounted for when evaluating internally-stateful (non-feature-based) baselines | High | **Surfaced and resolved during Project Phase 2 step 2.11's proof run** (`notebooks/03_validation_harness.ipynb`). Two distinct findings, not one: (1) a real bug — `_select_replay_anchors` originally spanned the input data's own full min/max date range rather than the verified clean 2004-2010 span, letting a candidate anchor's replay pattern run into the documented post-2010 missing-month gaps (A-012) or start with almost no prior fit history; this pulled the standard Tier 3 score to 0.894 (n_anchors=3) versus Baseline D's validated 0.6573. Fixed in source (`tiers.py`, commit `526cbf3`) and pinned with 3 regression tests (`tests/test_tiers.py`, commit `95329c5`) — with the fix, anchors and their full replay windows are proven to stay within the clean span. (2) A separate, non-bug limitation: even with the anchor fix, the STANDARD (row-wise) Tier 3 score for Baseline D's own persistence-plus-last-known-state logic remained at 0.8270 — still far from 0.6573 — because `run_tier3` scores each of the 18 replay offsets independently, never letting a stateful predictor's internal "last known value" update from earlier-in-pattern FULL-offset observations revealed *within the same replay window*. With both findings accounted for, the harness's core splitting/masking/offset/k bookkeeping is confirmed faithfully reproducing Phase 1's measured reality — no further bug is hiding underneath. | Validated | Project Phase 2, step 2.11 (`notebooks/03_validation_harness.ipynb`, sections 7/7b/13); any Phase 3+ candidate that reads "last observed value" through an explicit row-level feature (Project Phase 4) is scored correctly and fairly by the STANDARD harness as-is — this limitation is specific to stateful, non-feature-based baselines used as Phase 1 reference points |
